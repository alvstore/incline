Attendance operations views consolidate same-day member attendance rows by member while retaining raw rows as expandable audit detail, because turnstile bounce scans must not inflate visit counts.
Browser push mirrors existing in-app notifications through an event-driven queue; all new notification creation uses dispatchCommunication, keeping existing paid delivery channels unchanged.
Web Push signing keys are stored in a service-role-only table; endpoints are provider-allowlisted and lock-screen payloads contain no personal, financial, or health data.
Body progress places the render before a full-width summary; historical measurement silhouettes never fetch the latest scanner model, avoiding false before/after comparisons.
- Privileged (SECURITY DEFINER) functions used only by scheduled jobs, triggers or backend functions must have EXECUTE revoked from PUBLIC/anon/authenticated and granted to service_role only — signed-in users could otherwise call them directly.
- Public functions are closed by default: explicitly grant app/policy functions to authenticated. SECURITY DEFINER RPCs require visible `rpc_guard_applies()` + branch/self/role checks; CI verifies these to prevent cross-member access.
- Direct-entry guards use `rpc_guard_applies(function_name)` (reads `request.path = /rpc/<fn>`, skips service-role/no-JWT, triggers, nested definer calls and Storage/Realtime policy evaluation) so authorization is enforced only where a user calls the RPC directly — nested internal calls keep working without duplicated checks.
- Extensions live in the `extensions` schema (pg_trgm, vector moved there; pg_net is not relocatable): functions using vector/trgm operators must pin `SET search_path = public, extensions` so operators resolve while keeping the schema fixed.
- `BranchContext` owns role precedence (manager > staff/trainer > member) and selector visibility; mobile uses `MobileBranchBar` so scoping matches desktop.
- Members never call `purchase_pt_package` (the server refuses non-staff): member-mode PT selection files a high-priority front-desk task via `createTask` (same as the Renewal Concierge) so the desk confirms the trainer and sends the payment link; staff-mode callers must honour the RPC's `success:false` payload, not just the transport error.
- `access_logs.payload` stores scan metadata only, never camera frames or device tokens: every writer (mips-webhook-receiver, reconcile-mips-pass-records, any future importer) passes the raw event through `_shared/mipsPayload.ts#stripScanMedia` before insert, and `prune_access_log_media()` (called from `maintain_log_sizes()`) strips any oversized value older than a day — inline base64 made this one table 85% of the database and every feed load a multi-MB download.
- RLS policies must wrap per-user helper calls in `(SELECT …)` — `(SELECT has_any_role(auth.uid(), …))`, `branch_id = (SELECT get_user_branch(auth.uid()))`, `branch_id IN (SELECT managed_branch_ids(auth.uid()))` — never call `has_any_role()`/`manages_branch(uid, branch_id)` bare in a policy: bare calls are re-evaluated for every row (a 30-day attendance count took 1.3 s instead of 0.09 s). Use `managed_branch_ids()` (set-returning) instead of `manages_branch()` in policies.
- pg_cron jobs that invoke an edge function are gated with `WHERE EXISTS (<indexed pending-work predicate>)` on the job command itself (migration 0020 pattern), so an idle queue never spins up a function; the gate must be a strict superset of what the worker selects, and a new poller needs its gate and supporting partial index in the same migration.
- PT attendance is auto-marked by DB triggers via idempotent `pt_auto_attendance_evaluate` → `_pt_auto_apply` (one log row per package per IST day); gate scans must never fail because of PT logic, and manual `log_pt_session` stays the fallback.
- PT workspace keeps walk-in roster and optional appointments in Sessions; automatic attendance is a separate tab after Clients using the same attendance component in board-only mode, so moving UI never changes payout or booking engines.
- Referral workspace analytics come from the branch-guarded `referral_workspace_summary` RPC; keep referral charts server-aggregated so managers cannot infer other branches and clients do not download rows for trends.
- Gate denies only for base-membership causes; PT/store/add-on dues are AMBER (gate opens, desk alert, locks); per branch via settings.gate_tier_mode legacy|shadow|enforce.
- DB triggers call edge functions with `x-internal-token`, because stored service keys go stale on rotation and cause silent 401s.
- Stock purchases use the atomic `import_purchase_bill` RPC; imported products start unsellable and POS/store list only `is_sellable`, so cost is never shown as price.
- Annual-upgrade Analytics uses guarded summary/deadline helpers and dispatcher-log states, never backfilled stages. Cached page-zero preview and independent Sheet pagination keep browsing from changing the card.
